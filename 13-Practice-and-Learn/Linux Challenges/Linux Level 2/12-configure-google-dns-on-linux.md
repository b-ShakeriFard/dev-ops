# Configure Google Public DNS on Linux

## Challenge

Resolve a DNS configuration issue by adding Google's public IPv4 DNS server to the target Linux server.

Google's public IPv4 DNS addresses are:

```text
Primary:   8.8.8.8
Secondary: 8.8.4.4
```

The required primary server is `8.8.8.8`—not `4.4.4.4` or `4.4.8.8`.

## Step-by-Step Guide

### 1. Inspect the current resolver configuration

```bash
cat /etc/resolv.conf
```

DNS servers are represented by `nameserver` entries.

### 2. Edit the resolver configuration

```bash
sudo vi /etc/resolv.conf
```

Press `i` and add:

```text
nameserver 8.8.8.8
```

If a secondary Google DNS server is also required, add:

```text
nameserver 8.8.4.4
```

Press `Esc`, type `:wq`, and press Enter.

### 3. Confirm the saved entry

```bash
cat /etc/resolv.conf
```

You can specifically locate nameserver entries with:

```bash
grep '^nameserver' /etc/resolv.conf
```

### 4. Test hostname resolution

Use the system resolver:

```bash
getent hosts google.com
```

Other useful tests are:

```bash
nslookup google.com
dig google.com
```

If `dig` or `nslookup` is unavailable, `getent hosts` is often already installed and tests the resolver path used by normal applications.

To query Google DNS directly:

```bash
dig @8.8.8.8 google.com
```

## Persistence Warning

Directly modifying `/etc/resolv.conf` is often sufficient in a temporary challenge environment. On a permanent server, the file may be regenerated by NetworkManager, DHCP, or `systemd-resolved`.

For a NetworkManager connection, configure DNS persistently with:

```bash
nmcli connection show
sudo nmcli connection modify '<connection-name>' ipv4.dns '8.8.8.8 8.8.4.4'
sudo nmcli connection modify '<connection-name>' ipv4.ignore-auto-dns yes
sudo nmcli connection up '<connection-name>'
```

Only use `ipv4.ignore-auto-dns yes` when DHCP-provided DNS servers should be replaced rather than retained.

## Lessons Learned

- DNS translates hostnames such as `google.com` into IP addresses.
- `/etc/resolv.conf` contains the resolver's nameserver configuration.
- Google Public DNS uses `8.8.8.8` and `8.8.4.4` for IPv4.
- Successful IP connectivity does not prove DNS is working. A server may reach `8.8.8.8` while failing to resolve hostnames.
- `ping google.com` mixes DNS and network testing; `getent`, `dig`, and `nslookup` provide clearer DNS evidence.
- Configuration ownership matters: determine whether NetworkManager, DHCP, or `systemd-resolved` manages `/etc/resolv.conf` before making a production change.

## Interview Questions

### 1. What is the purpose of DNS?

DNS maps human-readable names to IP addresses and can also publish other records, including mail-routing and service information.

### 2. What is `/etc/resolv.conf`?

It is the traditional Linux resolver configuration file containing nameservers and optional search settings.

### 3. How do you distinguish DNS failure from network failure?

Test connectivity to an IP address first, then test hostname resolution:

```bash
ping -c 2 8.8.8.8
getent hosts google.com
```

### 4. Why might `/etc/resolv.conf` changes disappear?

A network-management service or DHCP client may regenerate the file when the connection restarts or the system reboots.

### 5. Which port does DNS normally use?

DNS normally uses UDP port 53 for routine queries and TCP port 53 for cases such as large responses and zone transfers.
